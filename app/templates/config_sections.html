Ce qui est faisable (et ce qui ne l'est pas) — exemples

Chaque ligne est une expression évaluée par Akvorado avec le langage Expr. Une expression peut tester une condition puis appeler une fonction de classification : condition && Classify…(…). Les valeurs classées sont normalisées par Akvorado (minuscules, caractères spéciaux retirés — seuls a-z 0-9 . + - subsistent). Le premier qui classe gagne : une fois un critère renseigné, aucune règle suivante ne peut le changer.

{% if section_key == 'exporter_classifiers' %}

Variables disponibles ici : Exporter.IP et Exporter.Name. Ce sont les deux seules — Exporter.Description n'existe pas, et les champs Interface.… sont absents du contexte de cette table.

Ce qui marche

  • ClassifyRegion("homelab") Sans condition : classe tous les exportateurs dans la région homelab. C'est l'une des 3 règles réellement en place. Résultat visible ensuite dans la colonne Region de Visualize.
  • Exporter.Name endsWith ".fr" && ClassifyRegion("france") Conditionnel : seuls les exportateurs dont le nom finit par .fr sont classés en région france. Les autres passent à la règle suivante.
  • Exporter.Name matches "^(clm|takas).*" && ClassifyRole("core") Expression régulière (syntaxe Go). Attention aux classes Perl : il faut doubler l'antislash — \\d, pas \d.
  • ClassifySiteRegex(Exporter.Name, "^([^-]+)-", "$1") Extrait une valeur du nom au lieu de l'écrire en dur : paris-rtr01 donne le site paris. Si la regex ne correspond pas, la règle n'écrit rien et rend false.

Ce qui ne marche pas

  • ClassifyConnectivity("transit") Fonction de l'autre table. ClassifyConnectivity, ClassifyProvider, ClassifyExternal, ClassifyInternal, SetName et SetDescription n'existent QUE pour les interfaces. Ici, Akvorado refuse de compiler la règle et ne démarre pas.
  • Interface.Description matches "transit" && ClassifyRole("edge") Variable hors contexte. Un exportateur n'a pas d'interface au moment où cette règle est évaluée : seuls Exporter.IP et Exporter.Name existent ici, et la règle est rejetée à la compilation.
  • Exporter.Name == "clm" Condition sans classification. L'expression est valide et s'évalue, mais n'appelle aucune fonction Classify… : elle ne produit donc strictement aucun effet. Une condition doit toujours être suivie de && Classify…(…).
  • ClassifyRegion("homelab") ; ClassifyRole("vm") Deux règles sur une ligne. Il n'y a pas de séparateur d'instructions : une ligne = une expression. Il faut deux lignes, ou les chaîner avec &&.

Fonctions de cette table : ClassifyGroup, ClassifyRole, ClassifySite, ClassifyRegion, ClassifyTenant, plus Reject() (écarte le flux) et Format(). Chacune des cinq a une variante …Regex(valeur, regex, modèle). Nuance non documentée par Akvorado (établie en lisant son code source) : une fonction sans Regex rend toujours true, même lorsqu'elle n'écrit rien parce que le critère était déjà classé — chaîner ClassifyRegion("a") && ClassifyRole("b") exécute donc toujours la partie droite.

{% else %}

Variables disponibles ici : Interface.Name, Interface.Description, Interface.Index, Interface.Speed, Interface.VLAN (tout en majuscules), et aussi Exporter.IP / Exporter.Name — une règle d'interface peut donc dépendre de l'exportateur.

Ce qui marche

  • ClassifyInternal() Sans argument ni condition : marque toutes les interfaces restantes comme internes. Placée en dernière ligne, c'est la règle « tout le reste » — utile sur un homelab où rien n'est du transit. Visible ensuite dans la colonne Boundary.
  • Interface.Name == "eth0" && ClassifyExternal() Marque une interface précise comme externe : le trafic qui la traverse est alors compté comme entrant/sortant du réseau.
  • Interface.Description matches "(?i)transit" && ClassifyConnectivity("transit") && ClassifyExternal() Chaînage de plusieurs classifications sur une même condition. (?i) rend la recherche insensible à la casse.
  • ClassifyProviderRegex(Interface.Description, "^\\S+?\\s(\\S+)", "$1") Extrait le nom du fournisseur depuis la description au lieu de l'écrire en dur. Noter les antislashs doublés, exigés par Akvorado pour les classes Perl.
  • SetDescription(Format("%s sur %s", Interface.Name, Exporter.Name)) Réécrit la description quand l'équipement n'en fournit aucune d'exploitable. Contrairement aux Classify…, SetName et SetDescription ne normalisent pas la valeur (majuscules et espaces conservés).

Ce qui ne marche pas

  • ClassifyRegion("homelab") Fonction de l'autre table. ClassifyRegion, ClassifyRole, ClassifyTenant, ClassifySite et ClassifyGroup n'existent QUE pour les exportateurs. Utilisée ici, Akvorado refuse la règle et ne démarre pas — le copier-coller depuis l'autre écran est le piège le plus fréquent.
  • ClassifyExternalRegex(Interface.Name, "^eth", "$1") Variante inexistante. ClassifyExternal() et ClassifyInternal() sont les seules à ne pas avoir de variante Regex : elles ne prennent aucun argument. Pour conditionner, utiliser Interface.Name matches "^eth" && ClassifyExternal().
  • ClassifyInternal() placée en première ligne Ordre destructeur. L'expression est valide, mais comme le premier qui classe gagne, elle marque tout en interne et aucune règle suivante ne pourra plus marquer quoi que ce soit en externe. Les règles spécifiques d'abord, le fourre-tout en dernier.
  • Interface.vlan == 10 && ClassifyConnectivity("iot") Casse du champ. Le champ s'écrit Interface.VLAN, tout en majuscules. Écrit autrement, il est inconnu et la règle ne compile pas. (Il exige par ailleurs que SrcVlan / DstVlan soient activés dans le schéma.)

Fonctions de cette table : ClassifyConnectivity, ClassifyProvider, ClassifyExternal, ClassifyInternal, SetName, SetDescription, plus Reject() et Format(). ClassifyConnectivity et ClassifyProvider ont une variante …Regex(valeur, regex, modèle) ; les quatre autres non.
